# 需求与阶段边界

目标：两位固定用户在手机上安排日程、记录体重与饮食、共同调整，没有竞争排名。中文界面，日期固定 Asia/Shanghai。不编造未知健康资料、库存、营养标签、完成记录或预测。

## 第一阶段：当前

- 生产只用管理员指定的“我/W”两个独立 Supabase 密码账号，并由管理员绑定同一空间。公开注册、邀请和自行建空间不作为入口；不配置 SMTP，不依赖邮件确认/重置投递。忘记密码由管理员在本地用受控工具处理，实际生产操作尚未执行。
- 私有基础档案、目标与原文约束。真实初始资料仅从 Git 忽略的私人文件导入，须本人核对；档案基线不伪造体重记录。
- 结构化手动日程；体重及可选腰围可补录、更正和删除。我/伴侣/共同只是查看范围，实际权限由数据库逐次校验固定身份及空间。
- 新增记录默认私有。类别开关与单条共享都确认才可被对方读取；代改另授权且留修改者审计，不能更改对方身份或共享状态；档案和删除仅本人。
- 编辑带预期修改时间，冲突明确报错。体重仅绘实际点，7 个自然日均值注明实际样本数，缺失不补造。
- 本人全量 JSON 导出、清除本人健康数据、退出空间；退出后不能自助重入，需管理员核实重关联。清除/退出不删 Auth 用户；备份留存边界另说明。
- 刷新读取云端最新状态，不宣称实时推送。前端不持久保存健康内容，Auth 会话由 SDK 维护。

## 第二阶段：计划

自然语言日程先展示可编辑确认卡，不猜人员、日期或限制；未经确认不入计划。手动生成每日计划需保存输入版本、生成时刻、来源及校验状态，双人校验一致后发布；日程变化使旧计划待更新，不覆盖锁定/手改版。餐食写清食物、份量、备餐与替代；运动写清目的、时段、热身、组次、休息、强度、放松和精简替代，校验总时长。固定器械、寝室替代、自由日及个人限制按已确认的私有档案执行；不自动当作完成或安排未知康复。每个真正使用的动作须有合法、准确、人工核对的示范与文字替代；未找到不伪造。

- 力量训练起点：每周两次并尽量相隔 48 小时；初期 1–2 组、8–12 次，辅助 10–15 次，保留约 3 次余力；至少一天无正式训练。不编造重量或完成记录。
- 固定器械动作包括腿举、坐姿划船、坐姿胸推、坐姿腿弯举、高位下拉、坐姿髋外展、腹部卷腹机；寝室替代为支撑单臂哑铃划船、地板哑铃卧推、坐下起立、死虫式，仅替代漏课。档案限制只能固定器械时不得加入自由重量。
- 私人档案指定的自由日不生成限制性菜单/训练，次日不补偿；未经评估不自动安排康复、跳箱、冲刺或大量跳绳。伤情恢复未知就保持未知。
- 动画需记录来源、授权/嵌入方式与人工核对日期；手机可播放、暂停、重播，并提供减少动态效果、文字步骤和停止信号。
- 餐食不过度限制正常主食与适量脂肪；库存未知写建议。备餐按冷藏、及时冷冻、保冷运输、彻底加热和避免反复加热提示。外卖或短期体重上涨不触发惩罚性少吃或加练。

## 第三阶段：自动计划

服务端 Cron 每日 12:00 UTC（上海 20:00）读取最新已确认输入，固定目标日及输入版本。任务唯一、防并发和重复发布，记录领取、完成、错误与重试；跨午夜按原应执行时间判断目标日。双人校验后原子发布，失败不能冒用旧计划；浏览器关闭不影响服务端任务。此阶段尚未实现。

20:00 后更新日程应标记旧计划待更新；用户主动再生成须保留历史版本。规则备用明确标注信息不足或 AI 失败，不能假称 AI 已完成。至少站内提示更新；手机推送需另授权。

## 第四阶段：饮食照片与 AI

私人照片上传限制格式、大小和定位等元数据，授权下载。对应本人明确同意服务商、用途、保存政策后，才可通过服务端调用 AI；密钥不进前端。估算需显示份量假设、区间和不确定性，可编辑并确认才入账，修正原记录、避免餐前餐后重复。不能识别时允许手动记录，不据估算惩罚饮食或运动。此阶段尚未实现。

餐食草稿还需允许修正食物种类、份量、烹调、油/酱汁、共享餐及吃掉比例；只累计已确认摄入，未记录不等于未吃。AI 日志脱敏，并提供状态、用量、限额及本人数据导出删除。

## 验收

按 [测试清单](TEST-CHECKLIST.md) 区分通过、失败、未运行和模拟。真实云端两账号、数据库权限和两台物理设备不能用本地构建或模拟代替；第三账号跨空间/越权在隔离的合成 Auth 夹具验证，不在生产创建第三用户。第一阶段可独立使用，不抢先实施后续阶段。
