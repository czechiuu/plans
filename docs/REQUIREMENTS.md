# 需求与阶段边界

目标：两位独立用户在手机上安排日程、查看具体计划、记录体重和饮食，共同调整；没有竞争排名。中文界面，日期固定 Asia/Shanghai。不牺牲睡眠、不编造未知信息、库存、营养标签、完成记录或预测。

## 第一阶段：本轮

- Supabase真实邮箱账号认证；不同账号通过一次性邀请加入同一最多两人的私人空间。
- 私有基础档案、目标与原文约束；初始资料从被忽略的私人文件导入，由对应本人确认。档案基线与真实体重记录分开，导入档案不会制造体重记录。
- 结构化手动日程，原文与确认字段共同保存；体重/可选腰围补录、修改、删除。
- 我/伴侣/共同只切换查看范围；数据库每次读取和写入校验当前身份和所属空间。
- 类别开关与单条记录共享必须同时确认；新增记录默认私有，不随开关自动共享。对方代改另行授权，禁止变更共享权限和所有者；档案仅本人可改。删除仅本人。
- 服务端保存修改者与时间；编辑冲突暴露而不静默覆盖。
- 体重只绘制实际点，7日自然日窗口平均注明实际记录数，缺失不补造、数据不足直说。没有精确预测。
- 支持本人全量JSON导出、本人健康数据清除、退出空间并撤销共享。账号本身的删除尚未实现；删除与备份保留规则单独说明。
- 刷新读取云端最新状态，首版不宣称浏览器推送。前端不存健康数据，Auth会话凭证由SDK维护。

## 第二阶段

- 自然语言日程：原文、提交上海时刻、人员、目标日期、空闲时段、意愿、固定安排、用餐和限制；歧义展示可编辑确认卡，不猜人员。未经确认不入计划。
- 手动生成每日计划，保存输入版本/生成时间/来源/校验状态。两人校验后一致发布；失败展示真实状态。新日程使旧计划待更新，保留版本，锁定/手改不静默覆盖。
- 餐食具体到食物、本人拳掌份量、购买/备餐方式、替代组合；运动包括目的、时段、热身、组次、休息、强度、放松、精简替代。各段时间含休息并校验总时长。
- 基础力量每周两次，尽量48小时；初期1–2组，8–12次，辅助10–15次，约3次余力。不编造重量，不自动等同完成；至少一天无正式训练。
- 固定器械起步动作：腿举、坐姿划船、坐姿胸推、坐姿腿弯举、高位下拉、坐姿髋外展、腹部卷腹机。寝室替代：支撑单臂哑铃划船、地板哑铃卧推、坐下起立、死虫式，仅替代漏课。
- 每个实际计划动作必须有合法且准确、逐个人工核对过的示范；记录来源、授权/嵌入方式和核对日期。手机播放/暂停/重播、减少动态效果、文字步骤和停止信号。未找到资源不伪造。
- 个人具体限制只取私有档案；仅允许固定器械时不得加入自由重量。档案指定的自由日不生成限制性菜单/训练，次日不补偿。伤情恢复未知不按康复完成处理，未经评估不得自动安排康复、跳箱、冲刺或大量跳绳。真实个人日期与伤情仅保存在私有档案中。
- 早餐蛋白质/主食/水果，正常主食与适量脂肪；份量与蛋白质粗略目标只作为私有档案中的起点。外卖/短期上涨不惩罚性少吃或加练。
- 备餐周一二冷藏、后续及时冷冻，及时冷却/保冷运输/彻底加热/不反复加热。库存未知写建议。

## 第三阶段

- 服务端Supabase Cron每日12:00 UTC（上海20:00），不依赖浏览器；读取最新已确认输入。
- 任务记录应执行时刻、固定目标日、输入版本、开始/完成、错误与重试；跨午夜延迟依据原应执行时刻，不依据重试当天。
- 同空间同目标日唯一任务、防并发及重复发布；双人校验后原子发布，部分失败不得冒用旧计划。无可靠历史不假定训练间隔。
- 20:00后更新日程显示待更新，主动再生成保留旧版本。规则备用明确标注信息不足/AI失败，绝不声称AI完成。
- 至少站内更新提示；手机推送需后续授权。

## 第四阶段

- 私有照片上传限制大小/格式、去定位等元数据，授权下载；外部AI只在服务端调用，密钥不进入前端。
- 首次AI调用前由对应本人同意具体服务商/资料/用途/保存政策；不同意仍可手动记餐。只发送当次所需资料，用户文本/OCR不当作指令。
- 名称“饮食估算”；可见食物、份量假设、能量区间及不确定因素，油/酱汁/比例未知不输出单一假精确数。
- 可编辑种类、份量、烹调、油/酱汁、共享餐、吃掉比例/剩余；草稿确认才入账，修正更新原记录，重复照片/餐前餐后不重复。
- 无法识别就说明并允许全手动。日汇总只加已确认摄入，未记录不等于未吃；不据此惩罚下一餐/加练，不估人的体脂/疾病/体形。
- AI状态、用量与限额、日志脱敏、照片与个人数据导出删除。

## 最后验收

按 TEST-CHECKLIST.md 的14项逐一记录通过、失败、未测试、模拟；真实设备/云端与人工动画核验不可被构建或本地模拟替代。第一阶段功能可独立使用，不等待后续完成。目标到期提示本人重确认，不自动延期或改目标，不为赶日期扩大缺口。
