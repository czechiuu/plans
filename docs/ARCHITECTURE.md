# 架构与费用

GitHub 存源码并通过 Pages 承载 Vite 原生 JavaScript 前端；Supabase 提供 Auth、Postgres 与 RLS。公开网页和 publishable key 只允许访问经服务端身份/空间权限授权的数据，不能成为管理员。两位用户无需独立服务器、消息队列或多个数据库。

生产只用两位指定密码账号。管理员已核实 Auth 用户，应用 003 并执行初始化 SQL，将两人绑定同一私人空间；真实业务仍待验证；普通网页不开放注册、邀请码或建空间。健康记录默认私有，共享和代改由数据库控制。登录标识是内部标识，不用于收信；SMTP 未配置，本轮不依赖邮件投递。遗忘密码由本地管理员工具调用官方 Auth Admin API，尚未生产执行。

| 页面 | 当前第一阶段 | 后续 |
|---|---|---|
| 今日/明日与日程 | 已确认的手动日程及本人/伴侣/共同范围 | 自然语言确认、计划来源/版本 |
| 体重 | 实际点、7 日均值与样本数、补录更正 | 可选训练完成 |
| 个人资料/隐私 | 本人档案、共享/代改、导出清除、退出 | AI 授权 |
| 饮食、动作与训练 | 未实施 | 餐食、合法动画、实际训练 |

扩展继续使用 Supabase Cron，每日 12:00 UTC（上海 20:00）运行；目标日由原应执行时间确定，任务按每人每日去重、防并发、分别校验发布，一个人失败不阻塞另一个人。不能用浏览器计时器或 GitHub Actions 当准时保证。照片使用私有 Storage，下载逐次授权；AI 仅由 Edge Functions 在本人授权和预算内调用。接口见 [HEALTH-API](HEALTH-API.md)，实际实现/部署/验收状态见 STATUS。

用户选择免费 Supabase 与公开代码仓库 `czechiuu/plans`；网页只含代码，真实健康资料不进仓库。免费项目的长期可用性须按实际上线情况再评估，不自动付费。前端只含项目 URL 和 publishable key；密码、服务端密钥、未来 AI 凭据不写仓库或浏览器。当前零 AI 调用，未启用照片、推送或自动计划。
