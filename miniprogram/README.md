## 打开项目

1. 用微信官方开发者工具导入本目录，项目类型选“小程序”，不选云开发模板。`project.config.json` 已填写用户提供的 AppID；由有开发权限的本人扫码登录工具。
2. 保持“校验合法域名”开启（仓库 `urlCheck:true`）。不能用关闭校验来验收；填写 AppID 不能证明真实后端连接。
3. 已含 `lib/shared.js` 和 `config.js`。`config.js` 仅有现有公开 Supabase URL / publishable key；不需要 npm 构建。若修改共享动作或校验源码，从仓库根运行 `pnpm build:miniapp`，使用原网站的公开环境配置生成；不填管理密钥。
4. 后续微信后台操作、域名表和真机步骤见 [接入交接](../MINIAPP_HANDOFF.md)、[验收与操作说明](../docs/MINIAPP-ACCEPTANCE.md)。AppSecret、AI Key、service_role 均不进入项目。
5. 本轮新版导入包为 `dist-native/plans-native-experience-0.1.1-20261015.zip`（仓库根路径）；体验二维码仅私有交付，不包含在源码包或 Git 中。

## 日常操作

- 登录：选择“我”或 W，用现有密码。断网中断续期后，联网点“重新连接原会话”。退出只注销当前设备会话。
- 今日：读本人当日计划与已确认摄入；拍照记餐、记录体重和开始训练在顶部。
- 明日：填写自然语言，选择已授权服务解析，逐项核对保存；也可直接手动确认。仍由服务器北京时间 20:00 生成。任务状态、错误和重试保持可见；生成按钮是主动更新，不能当作自然定时验收。
- 记录：拍照先在本机缩小、净化为 PNG，保存私有草稿并上传；需要估餐时再选择本人已授权服务。修改食物、份量和油酱，明确确认才计入；后续餐食建议单独请求、审阅后采用，可撤销。发送结果未知时沿用原提交编号重试。
- 体重：默认上海今天，可补录，单位 kg；可选时刻、腰围和备注。新记录默认私有。
- 训练：只开始今天的正式训练计划，逐组保存、休息计时、暂停、继续和部分完成；其他动作库仅供查看。GIF 只在打开时加载，八项原视频当前不在小程序内播放。
- 趋势：实际体重、七日平均和两周训练记录对比；缺失不填零。
- 设置：逐用途供应商授权、个人限额、共享类别、夜间计划方式和当前设备退出。小程序不自动改变这些选择。
