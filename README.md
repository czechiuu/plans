## 日常使用

1. 各自登录后，在“明日安排”写原始日程，核对日期、时间、运动类型和限制再保存；需要时明确选择规则、OpenAI 或 DeepSeek 生成次日计划，查看完整三餐和训练后再使用。后台以每天上海 20:00 为任务锚点、每五分钟领取；实际20:00与随后重复调度已用合成资料验证，晚间请刷新查看自己的任务和计划状态，不把排队当作已生成。
2. “今日”先显示拍照记餐与完整计划。照片或纯文字餐食都先核对食物、份量、油酱、剩余和实际吃掉比例；估算是范围草稿，本人确认后才计入。确认餐食后可单独请求后续餐食调整，查看建议再由本人应用或撤销，原计划和历史仍可查。
3. 力量训练在“训练”按实际逐组记录、休息、暂停或因不适停止；羽毛球等已完成运动可只填写完成日期与实际时长。计划不自动等于完成记录，趋势分别展示力量和羽毛球。
4. 首页或趋势顶部点“记录体重”，默认上海今天，也可补录；保存后查看趋势和最近记录。新资料默认私有，共享、代改和每项 AI 用途由本人控制，可撤销。设置里先看发送范围及本月费用上限；预算不足会停止付费请求，不会自动提高额度。另一设备需刷新读取服务器最新记录，站内提示不是手机推送。

## 本地运行

需要 Node.js 22+、pnpm。复制 [.env.example](.env.example) 为被忽略的 `.env.local`，仅填两项公共配置；密码、会话、服务端密钥和私人档案不得提交。

```sh
pnpm install --frozen-lockfile
pnpm dev
pnpm test
pnpm test:concurrency:health
pnpm test:concurrency:ai
pnpm test:concurrency:activities
pnpm build
pnpm build:edge
```

本地、隔离数据库、真实 API 与网页的证据与边界见 [测试清单](docs/TEST-CHECKLIST.md)。本人 JSON 导出包含 009 以后新生成的输入快照；旧任务不回填。网页自然 20:00 及随后重复调度的历史通过证据已保留；原生及双手机完整流程尚未验收。
